How an application reaches a Mac and how the system learns what it is

A bundle arrives by one of five routes, carries its own description in a property list, and is registered with Launch Services, which from then on decides what the app opens and which app opens a document. This page is the routes, the bundle, the two registrations a reader cares about (document types and URL schemes), and what a Tauri build writes for each.

What "install" means on macOS. For a drag-installed app, nothing is recorded anywhere at the moment of installation except the file copy. The registration (§6) happens when the Finder sees the bundle or the app first launches; the residue in ~/Library begins at first run. This is why there is no system uninstaller for such apps, and why Apple's own uninstall procedure is a drag to the Trash (removal).

The bundle

factkindsource
Tauri's tauri build --bundles app, run on a Mac, produces <productName>.app with Contents/ holding Info.plist, MacOS/<binary>, Resources/ (the icon as icon.icns and bundle.resources), _CodeSignature/, and when used Frameworks/, PlugIns/, SharedSupport/. Files from bundle.macOS.files are added under Contents/.documentedT1 · Bundle
Tauri sets the binary name, version, bundle identifier and minimum system version in Info.plist itself; an Info.plist beside tauri.conf.json is merged in for other keys, and overriding a generated value such as the version "can cause conflicts".documentedT1 · Info.plist
bundle.macOS.minimumSystemVersion defaults to "10.13", writes LSMinimumSystemVersion, is ignored in tauri dev; null removes the key; an empty string is invalid.documentedT4 · bundle.macOS
GUI apps on macOS "don't inherit $PATH from shell dotfiles"; Tauri points at the fix-path-env-rs crate.documentedT1
A sidecar (bundle.externalBin) is a binary named with the host's target triple beside the configured path (binaries/dreader-aarch64-apple-darwin for Apple silicon); the app invokes it by file name through the shell plugin with a capability entry (shell:allow-execute, "sidecar": true). Tauri's page does not say where in the bundle it lands.documentedT7
The sidecar lands in Contents/MacOS/ beside the app binary: dreader's installed bundle holds Contents/MacOS/dreader and Contents/MacOS/dreader-app, and its install check fails when the first is missing.observedO1 · 2026-10-13; O2 · DR-0044
dreader's installed bundle, 2026-10-13: Contents/{_CodeSignature, Info.plist, MacOS, Resources}; Resources/icon.icns only; no Frameworks.observedO1

§4

Document types

factkindsource
CFBundleDocumentTypes is "the document types supported by the bundle", an array of dictionaries. Its keys include CFBundleTypeName ("the abstract name for the document type"), CFBundleTypeRole ("the app's role with respect to the document type"), LSItemContentTypes ("the document file types the app supports", as uniform type identifiers), LSHandlerRank ("the ranking of this app among apps that declare themselves as editors or viewers of the given file type"), CFBundleTypeIconFile. Available on macOS 10.0 and later.documentedA11
The allowed values of CFBundleTypeRole and LSHandlerRank are not on Apple's page as read. Tauri's reference lists them for its own fields: role Editor (default), Viewer, Shell, QLGenerator, None; rank Default (default), Owner, Alternate, None.documentedT4 · fileAssociations
Tauri's bundle.fileAssociations entries map: ext (required; a leading dot is stripped), name → CFBundleTypeName (defaults to the first extension), role → CFBundleTypeRole, rank → LSHandlerRank, contentTypes → LSItemContentTypes, exportedType → UTExportedTypeDeclarations, mimeType → public.mime-type in the exported type's tag specification; description is Windows only.documentedT4 · fileAssociations
dreader declares EPUB (org.idpf.epub-container, role Viewer, rank Default) and PDF (com.adobe.pdf, role Viewer, rank Alternate). Tauri also wrote the legacy CFBundleTypeExtensions key beside LSItemContentTypes for each.observedO1; D · tauri.conf.json
Rank Default for EPUB means dreader offers to be the EPUB opener; rank Alternate for PDF means it is offered without claiming the default from Preview (PRD-0002 R-I6, R-P1).familyD · PRD-0002

§5

URL schemes

factkindsource
CFBundleURLTypes is "a list of URL schemes (http, ftp, and so on) supported by the app", an array of dictionaries with CFBundleURLName ("the abstract name for this type"), CFBundleURLSchemes ("the URL schemes supported by this type"), CFBundleTypeRole, CFBundleURLIconFile. macOS 10.0 and later.documentedA10
Tauri's deep-link plugin takes desktop schemes from tauri.conf.json > plugins > deep-link > desktop > schemes; "Registering deep links at runtime is not possible on macOS, so deep links can only be tested on the bundled application", installed in /Applications. The app receives a URL through on_open_url (Rust) or onOpenUrl (JavaScript), and get_current at startup for a launch from a link.documentedT6
Whether the plugin writes CFBundleURLTypes into the macOS Info.plist: Tauri's page documents that key for iOS only; the macOS mechanism is not stated.unverifiedT6
Launch Services binds a URL to an app by scheme, choosing among claimants by the same ordering as documents minus the creator-signature step (§6).documentedA13 · URLs
dreader's planned scheme is dreader://open?path=, "so the catalog's record pages can link to the reader" (PRD-0001 R28); not built at 7a13aa1.familyD · PRD-0001

§6

Launch Services: registration and binding

factkindsource
Launch Services keeps "a central data structure" in which "it records all of the pertinent information about applications and the kinds of document files and URLs they are capable of opening", read from each app's Info.plist.documentedA13 · Registration
When an app is registered: at boot or a new user's login, "a built-in background tool … automatically searches the Applications folders in the system, network, local, and user domains and registers any new applications it finds there"; "the Finder automatically registers all applications as it becomes aware of them, such as when they are dragged onto the user's disk or when the user navigates to a folder containing them"; a custom installer calls LSRegisterURL. The guide names no command-line tool and does not mention the Installer app.documentedA13 · Registration
Re-registration after an Info.plist change: call the register function with inUpdate true, or touch the bundle so its modification time is newer than the database record.documentedA13 · Registration
Binding, in order: a user-specified binding from the Finder's Get Info "Open With" (per item, or "Change All" for the type) wins, and such bindings are "not user-specific but systemwide"; otherwise apps claiming the file's extension and then its type are found and, among several, preferred by native over Classic, boot volume over others, local over remote, then latest CFBundleVersion. Ties are broken "in an unspecified manner" and Apple "reserves the right to change the selection criteria". The guide predates LSHandlerRank and does not mention it.documentedA13 · Binding
The command-line tool lsregister, inside the LaunchServices framework, registers (-f), unregisters (-u), and dumps (-dump) the database. It is not in Apple's documentation as read; dreader's installer, uninstaller, and leftover check use it, and the check passed on 2026-10-13 with -dump showing nothing for the test identifier after -u.observedO2 · DR-0046
open -b <bundle id> <file> opens a file in the registered app wherever its bundle lives; dreader's CLI uses it in a release build and falls back to the app binary beside itself when Launch Services knows no such app.observedO2 · DR-0044

§7

Relationships

  • Places. The bundle lands in the local or user domain's Applications; the Caskroom and the receipts are local-domain records of the arrival (places §2).
  • The gate. A bundle that arrives by download carries quarantine, and the signature inside _CodeSignature is what Gatekeeper evaluates (gate §1, §4). A sidecar is signed with the bundle, so an unsigned or differently signed sidecar fails the whole bundle's notarization (DR-0050).
  • Removal. The registration made here is the one piece of residue that is not a file under the user's control; it is undone by name (removal §4).
  • dreader. Its bundle identifier is the key under which four other places are named (dreader §4).

§8

Gaps and unverified claims

  • Apple's current statement of Launch Services registration and binding, with LSHandlerRank, was not found; the Launch Services Programming Guide is an archive document and the per-user "Always Open With" binding is not described in it.
  • The receipts' on-disk location is deliberately unstated by pkgutil's manual; /var/db/receipts is a common account and is not on this page as a fact.
  • Whether Tauri writes CFBundleURLTypes for macOS from the deep-link plugin's configuration is unverified (§5).
  • The Mac App Store route is covered only as far as the sandbox requirement; its receipt and update mechanisms are not on this page.
  • The DMG's internal anatomy (whether the Applications icon is a symbolic link; the hdiutil step) is not on Tauri's page as read.
