What a macOS application leaves on a Mac, and how it gets there

An application arrives in one of a few ways, is registered with the system, runs under a gate, writes to a known set of places as it runs, and is removed by a procedure that reaches only some of them. This atlas is that mechanism in five pages, with one application, dreader, mapped onto it for its public release.

§1

The mechanism, in five steps

Each step is one page. The arrows are the dependencies: a step can only be understood with the one before it in mind.

1placesThe file system's domains and the directories an app may write to. Apple's rule: an app writes nothing outside ~/Library unless the user directs it. Everything after this page is about which of these places each actor touches.
2arrivalHow an app bundle reaches /Applications (a disk image, an installer package, Homebrew, the App Store, a build from source), what a bundle contains, and how Launch Services learns what it opens.
3gateWhat stands between a downloaded bundle and its first launch (quarantine, Gatekeeper, signing, notarization) and between a running app and the user's files (the privacy permissions).
4removalWhat Apple's uninstall procedure removes, what it leaves in the places of step 1, and the order a complete uninstaller follows.
5dreaderOne application on this map: every file it keeps and its format, every place it writes, which vendor fact each of its release decisions rests on, and what its public release still needs.

§4

dreader, in one paragraph

dreader is an EPUB and PDF reader built with Tauri 2, whose record (library, positions, highlights, notes) is JSON files the reader owns, indexed by a SQLite database that can be rebuilt. At commit 7a13aa1 it installs from a source checkout into /Applications, ad hoc signed; its data root resolves from an environment variable, then a preference, then ~/Library/Application Support/dreader/; it keeps an inventory of every place it writes and ships an uninstaller that removes them all, asking only about the record. Its public release still needs a Developer ID signature with notarization, a disk image, a Homebrew tap, a guide, and a decision on updates. The dreader page has every file, every format, and every one of those facts with its source.

§5

How to read a page

  • The block under the title says what version of the subject the page was read against and when. A fact is true at that version; the change record at the end keeps the old fact when a release changes it.
  • A row's source mark (A3 · Uninstall) names a document in the page's sources list and the section the fact came from. Verbatim vendor wording is quote-marked.
  • A row's kind mark says whether the fact is documented, observed, from a family document, or unverified. A fact the vendor does not document and the family observed is never shown as documented.
  • Each page's gaps section lists what the author knows to be missing, so "not on the page" can be told from "not known".
