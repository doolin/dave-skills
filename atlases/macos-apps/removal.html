What uninstalling removes, what it leaves, and the order a complete uninstaller follows

Apple's procedure for an app without an uninstaller is a drag to the Trash, which removes the bundle. Everything the app and the system wrote on its behalf stays. This page is Apple's procedure, the residue by place as Homebrew's cask cookbook enumerates it, the per-mechanism undo for the things that are not files, and the order dreader's uninstaller settled on after its tests.

§1

Apple's procedure

factkindsource
In the Finder's Applications folder: if the app is in its own folder, look there for an uninstaller ("Uninstall [App]" or "[App] Uninstaller") and run it; otherwise drag the app from Applications to the Trash. The app "is removed permanently the next time you or the Finder empties the Trash"; "If you have files that you created with the app, you may not be able to open them again." To keep it, select it in the Trash and choose File → Put Back.documentedA3 · Uninstall, macOS 26
Apps the Mac requires cannot be removed (Mail, Music, Books, Notes, Podcasts, Maps, News, Stocks among them). An app reported in use must be closed first; failing that, restart or start in safe mode.documentedA3
The page says nothing about preferences, caches, support files, or Launch Services; the procedure removes the bundle. Everything in §2 remains.documentedA3 (a closed procedure; the residue list is §2's)
For a package install there is no uninstaller in macOS: pkgutil --forget <id> "discards the receipt data" and "leaves the installed files untouched"; pkgutil --files <id> lists what to remove by hand.documentedM1

§3

Homebrew's two stanzas

factkindsource
uninstall removes what the cask installed. For most casks Homebrew works it out from the artifacts; a cask using pkg or installer must state it. Its keys, run in the cookbook's fixed order and never the file's: early_script, launchctl (job ids, wildcards allowed), quit (bundle ids, sent the standard quit event), signal (signal and bundle id pairs for processes that ignore quit), login_item, kext, script, pkgutil (package ids, "the most useful key", preferred over delete), delete (absolute paths, last resort), trash, rmdir (empty directories, recursively).documentedH1 · uninstall
zap takes the same keys, prefers trash over delete, and "is never run by default": the user runs brew uninstall --zap <cask>. The manual: --zap "Remove all files associated with a cask. May remove files which are shared between applications."documentedH1 · zap; H2 · uninstall
dreader's planned cask carries "a zap stanza taken from the footprint inventory", and brew install --cask then brew uninstall --zap must leave its leftover test passing (DR-0052).familyD · DR-0052

§4

The things that are not files, and the order

Four kinds of residue are not files under the user's control and need a tool each. dreader's uninstaller found two ordering rules by running against a real account; both are recorded here as observed.

residueundofactkindsource
Running processesquit, then waitHomebrew's quit runs before any file step. dreader: "a quit without a wait let the app write its preferences back after the delete", so the uninstaller quits and waits until the processes are gone before anything else.observedH1; O2 · DR-0046
Launch Services registrationlsregister -u <bundle>Apple's guide describes registration and re-registration, not removal; a deleted bundle's record stays until the database is rebuilt. dreader unregisters by name, "so another app becomes the default for EPUBs" (R-U5), and its check dumps the database to confirm.observedA13; O2 · DR-0046
The preferences domaindefaults delete <bundle id>, then the fileApple: never edit the file directly. Observed on macOS 26: defaults delete leaves an empty plist, still listed by defaults domains; deleting the file first is undone, because the preferences daemon writes it back with its cached values. So: domain first, then the empty file.observedA14; O2 · DR-0046
WebKit's directoriesremove under the account's homeWebKit writes under the account's home from the user database, whatever HOME says, so a scratch HOME does not isolate them; dreader's check builds the app under a test identifier instead, so every account-wide place it touches is the test's.observedO2 · DR-0046

The order is dreader's (D · footprint.md, DR-0046), given here as the worked example of the rules above; steps 1, 2 and 5 carry the observed constraints.

§5

Relationships

  • Places. §2 is the places page read backwards: every directory that carries the app's name or identifier (places §3, §7).
  • Arrival. The registration undone in §4 was made at arrival; a package's receipt is the record of what arrived (arrival §6, §1).
  • The gate. The privacy grants reset in §4 were given at first access; the Gatekeeper exception has no documented undo (gate §6, §3).
  • dreader. Its inventory is the list that its leftover check reads, so a new write location fails the check until it is listed (dreader §4).

§6

Gaps and unverified claims

  • Apple publishes no list of the residue a drag-to-Trash leaves; §2 rests on Homebrew's list and on one app's observed footprint.
  • How Launch Services prunes records for deleted bundles (at login, at a rebuild) was not found in the guide read.
  • The Open Anyway exception's storage and revocation are unverified (§4).
  • lsregister and the preferences daemon are undocumented by Apple in the pages read; their behaviour here is observed through dreader's tests, on macOS 26 only.
