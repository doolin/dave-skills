Atlases · macOS applications · gate

What stands between a downloaded app and its first launch, and between a running app and the user's files

Two gates. The first is Gatekeeper: a downloaded bundle is quarantined, and on first open macOS checks that it is signed by an identified developer, notarized by Apple, and unaltered; what the user can do when it is not changed in macOS 15. The second is the privacy system: an app reads Documents, Desktop, or Downloads only with the user's grant. Both are per machine and per user, both survive the bundle's deletion, and both are what a public release must satisfy.

§1

Quarantine

factkindsource
LSFileQuarantineEnabled is an Info.plist key, "a Boolean value indicating whether the files this app creates are quarantined by default"; macOS 10.0 and later. An app that downloads (a browser) sets it, and so marks what it saves.documentedA12
Gatekeeper "requests user approval before downloaded software opens for the first time, to prevent users from running executable code they thought was a data file", and "tracks the provenance of files written by downloaded software".documentedA6 · Gatekeeper
The mark is an extended attribute named com.apple.quarantine, readable and removable with xattr. Not confirmed from an Apple document at this version; common account.unverified—
A file fetched with curl or copied from a source checkout carries no quarantine, so a developer's own build never meets the gate the way a tester's download does. dreader's signing ticket therefore requires the proof to be "downloaded through a browser (so it carries quarantine) on a clean macOS 15 account".familyD · DR-0050

§2

Gatekeeper's check

factkindsource
Gatekeeper applies to "apps, plug-ins, and installer packages downloaded from outside the App Store". It checks that the software "is from an identified developer, notarized by Apple as free of known malicious content, and unaltered".documentedA6 · Gatekeeper
Default policy: "all software is checked for known malicious content the first time it's opened, regardless of how it arrived"; by default software must be "signed by the App Store, or signed by a registered developer and notarized by Apple". Users and organisations can restrict to the App Store only; Gatekeeper can be turned off; a device management service can forbid overrides.documentedA6 · Gatekeeper
Apple's three layers against malware: prevent launch (the App Store, and Gatekeeper with notarization), block execution (Gatekeeper, notarization, XProtect), remediate (XProtect). Apple can issue revocation tickets for apps found malicious, including ones it had notarized, which macOS checks for in the background.documentedA15
Against plug-ins bundled with benign apps, Gatekeeper "can open apps from randomized, read-only locations", which stops bundled plug-ins loading automatically. This is the mechanism by which a quarantined app may run from a translocated path rather than /Applications; the page does not use the word translocation.documentedA6 · Gatekeeper
spctl -a -vv --type exec <app> prints Gatekeeper's verdict. On this Mac, /Applications/dreader.app (ad hoc signed): rejected.observedO1 · 2026-10-13

§3

The override, at macOS 26

factkindsource
Opening an app "not registered with Apple by a known developer" shows a warning dialog (wording not quoted on the page). To open it anyway: System Settings → Privacy & Security → under Security, click Open → click Open Anyway → enter the login password. "Open Anyway" "is available for about an hour after you try to open the app." The app is then "saved as an exception to your security settings" and opens by double-click thereafter.documentedA4 · macOS 26
Apple's own caution on the same page: "Overriding security settings to open an app is the most common way that a Mac gets infected with malware."documentedA4
Before macOS 15: "In macOS Sequoia, users will no longer be able to Control-click to override Gatekeeper when opening software that isn't signed correctly or notarized. They'll need to visit System Settings > Privacy & Security to review security information for software before allowing it to run." Announced 2024-08-06, with the recommendation to notarize software distributed outside the App Store.documentedA7
The macOS 26 user guide page does not mention Control-click. The macOS 27 page, which the support site serves by default, has the same steps.documentedA4; A4 at /27/mac/27
Tauri: ad hoc signing "does not stop macOS from requiring users to approve the app in Privacy & Security settings"; a free developer account "cannot notarize, so the app still shows as unverified when opened".documentedT2
dreader's alpha may ship ad hoc signed; its README then gives these macOS 15 steps with screenshots (PRD-0002 R-A2). Its public release must open with no warning (goal 2, R-P2).familyD · PRD-0002

§4

Signing identities and the hardened runtime

factkindsource
Signing for distribution needs an Apple Developer account (99 USD a year, or a free one for testing and development only) and an Apple device. Outside the App Store the certificate is "Developer ID Application"; only the Account Holder can create one. A certificate signing request made on a Mac is uploaded to Apple and the .cer downloaded.documentedT2 · Requirements, Certificates
Local signing: the identity is the keychain entry name listed by security find-identity -v -p codesigning, set in bundle.macOS.signingIdentity or APPLE_SIGNING_IDENTITY. For CI: the certificate exported as .p12, base64-encoded into APPLE_CERTIFICATE with APPLE_CERTIFICATE_PASSWORD.documentedT2 · Configuring
Ad hoc signing: identity - signs "without an Apple-authenticated identity"; "useful on Apple Silicon, where apps from the internet must be signed".documentedT2 · Ad-hoc
bundle.macOS.hardenedRuntime defaults to true; entitlements names a file applied at signing time.documentedT4 · bundle.macOS; T1 · entitlements
Notarization prerequisites on the signature: every executable signed and valid; a Developer ID certificate (not Mac Distribution, ad hoc, Apple Development, or local); the hardened runtime on for app and command-line targets; a secure timestamp; no com.apple.security.get-task-allow; linked against the 10.9 SDK or later; ASCII XML entitlements.documentedA8 · Prerequisites
Entitlements a notarized app may still need: com.apple.security.cs.allow-jit or allow-unsigned-executable-memory for a JavaScript engine or function-pointer overrides; disable-library-validation for certain drivers. Plug-ins inherit the host's entitlements.documentedA8 · Entitlements
dreader's installed bundle, 2026-10-13: codesign -dv reports Signature=adhoc, flags 0x10002(adhoc,runtime) (the hardened runtime flag is set even on the ad hoc signature), TeamIdentifier=not set, Runtime Version=26.5.0, arm64 only.observedO1
dreader's plan: Developer ID Application, hardened runtime, no get-task-allow, entitlements start empty with any exception recorded with its reason; the sidecar CLI signed too; bin/release refuses a dirty tree or an untagged HEAD (PRD-0002 R-P2, R-P3; DR-0050).familyD · DR-0050

§5

Notarization and stapling

factkindsource
Notarization is "an automated system that scans your software for malicious content, checks for code-signing issues, and returns the results"; it is not App Review. If it passes, the notary service issues a ticket that the developer staples to the software and that Apple also publishes online for Gatekeeper to find. Apple keeps an audit trail so that tickets for software signed with an exposed key can be revoked.documentedA8 · Overview
Requirements by version: in macOS 10.14.5, software signed with a new Developer ID certificate and all new or updated kernel extensions must be notarized to run; in macOS 10.15, all software built after 2019-06-01 and distributed with Developer ID must be notarized. Mac App Store software needs none, because review includes equivalent checks.documentedA8 · Requirements
What can be notarized: macOS apps, non-app bundles such as kernel extensions, disk images (UDIF), flat installer packages, plug-ins; pre-existing software as a disk image, installer package, or ZIP archive containing the app. In macOS 10.15 and later, apps load quarantined plug-ins only if notarized.documentedA8 · Formats
Tools: notarytool uploads to the notary service; stapler attaches the ticket; the Notary API is the web interface. Scanning "usually takes less than an hour". At first launch, "a ticket, either online or attached to the executable, tells Gatekeeper that Apple notarized it", and Gatekeeper then shows "descriptive information in the initial launch dialog".documentedA8 · Tools, Gatekeeper
Tauri notarizes inside tauri build when either the App Store Connect API variables (APPLE_API_ISSUER, APPLE_API_KEY, APPLE_API_KEY_PATH) or the Apple ID variables (APPLE_ID, APPLE_PASSWORD as an app-specific password, APPLE_TEAM_ID) are set; notarization "is required with a Developer ID Application certificate"; --skip-stapling exists, so stapling is part of the normal flow. Whether the .dmg is itself signed is not stated on Tauri's pages.documentedT2 · Notarization; T3
Verification after the fact: spctl -a -vv --type exec reporting source=Notarized Developer ID, and xcrun stapler validate on the .app and the .dmg, are dreader's acceptance checks.familyD · DR-0050
Homebrew's main cask repository "disables casks that fail Gatekeeper from September 2026", which is dreader's stated reason that a public release has to open with no warning.familyD · DR-0050, citing dreader's release research §2

§6

The privacy permissions for files

factkindsource
"Some apps and websites can access files and folders in your Desktop, Downloads, and Documents folders." The grants are in System Settings → Privacy & Security → Files & Folders, one switch per app per location, and are turned off in the same list. The page covers only those three folders; it does not mention removable or network volumes, or Full Disk Access.documentedA5 · macOS 26
How an app first obtains the grant (the system prompt on first access) is not described on the page read.unverifiedA5
tccutil, the command-line tool for these grants, prints Usage: tccutil reset SERVICE [BUNDLE_ID]; it resets, it does not grant. tccutil reset All <bundle id> clears every grant for one app.observedO1 · 2026-10-13
The grants are keyed by bundle identifier and outlive the bundle; dreader's uninstaller runs tccutil reset All com.clubstraylight.dreader (PRD-0002 R-U5).familyD · footprint.md; DR-0046
dreader's library roots are under ~/Documents on the author's Mac, so the first scan "triggers macOS access prompts"; the app "asks once through the system dialog; CLI inherits the terminal's grant" (PRD-0001 §16, Q6). A sandboxed build would instead need security-scoped bookmarks (places §5).familyD · PRD-0001

§7

Relationships

  • Arrival. Quarantine is set by the route (a browser download sets it; a source build and curl do not), and Gatekeeper evaluates the signature inside the bundle (arrival §2).
  • Places. The privacy grants govern reading ~/Documents, ~/Desktop, ~/Downloads; Apple's file-system rule governs writing there (places §2).
  • Removal. The Open Anyway exception and the privacy grants are both keyed to the app and survive its deletion; only the grants have a reset tool (removal §4).
  • dreader. Its current signature is ad hoc and rejected by Gatekeeper; its release plan is the Developer ID path on this page (dreader §6).

§8

Gaps and unverified claims

  • The quarantine attribute's name and its fields are unverified against an Apple document at this version (§1).
  • The exact wording of the macOS 26 warning dialog is not on Apple's page and was not captured on this Mac.
  • Full Disk Access, and how an app first asks for a folder grant, are not on the user guide page read (§6).
  • Whether the Open Anyway exception can be revoked, and where it is stored, was not found.
  • App translocation (running from a randomized read-only path) is described by Apple only in the plug-in sentence quoted in §2; its effect on an app that locates files relative to its bundle is not on this page.
  • Apple's notarization page as read does not show the xcrun notarytool and xcrun stapler command lines; dreader's ticket carries them from the Tauri flow.
