Where an application may write, and what each place is for

macOS divides the file system into four domains and gives every application the same few directories to write in. This page is those directories as Apple defines them, the preference system that owns one of them, the paths a Tauri application resolves to, and the places that exist on a real Mac but appear in no Apple list.

§1

The four domains

Apple's File System Programming Guide divides the file system "into multiple domains" that "separate files and resources based on their intended usage". Each has its own Library.

§3

The Library directories an app uses

Apple's rule for which Library an app writes to: "In macOS, it is the app's sandbox directory or the current user's home directory (if the app is not in a sandbox)." The directories below are the ones that matter to an application and its uninstaller; Apple's full list has thirty-six.

subdirectoryApple's descriptionconvention for the pathkindsource
Application Support"Contains all app-specific data and support files. These are the files that your app creates and manages on behalf of the user and can include files that contain user data." Elsewhere: "Use this directory to store all app data files except those associated with the user's documents." "Resources required by the app to run must be placed inside the app bundle itself.""a custom subdirectory whose name is that of your app's bundle identifier or your company", for example ~/Library/Application Support/com.example.MyApp/documentedA2 · Application Support; A1 · Library
Caches"Contains cached data that can be regenerated as needed. Apps should never rely on the existence of cache files."~/Library/Caches/com.example.MyApp/documentedA2 · Caches

Saved Application State, WebKit, HTTPStorages, Group ContainersIn none of Apple's thirty-six entries. Each exists on this Mac and holds per-application directories; §7.observedO1 · 2026-10-13
Name or identifier. Apple's convention for Application Support and Caches is a subdirectory named by bundle identifier or company. Frameworks that write on an app's behalf (WebKit, AppKit's saved state, the preferences system) always use the bundle identifier, so an app that names its own folder by product name, as dreader does with Application Support/dreader, has two names on disk: its own under dreader, the frameworks' under com.clubstraylight.dreader. An uninstaller has to know both.

§4

The preferences domain

factkindsource
Preferences are grouped into domains; each preference is a domain, a name, and a property-list value (data, string, number, date, array, dictionary). Preferences are per user; sharing between users is not supported.documentedA14 · Preference domains
The application domain is tied to the bundle identifier. Its file is $HOME/Library/Preferences/<ApplicationBundleIdentifier>.plist. The page says not to modify the file directly, but it may be inspected while debugging.documentedA14 · Application domain
Lookup order, first match wins: the argument domain (command-line arguments, volatile), the application domain, the global domain (NSGlobalDomain, for system values such as AppleLanguages), the languages domains, the registration domain (defaults set in code).documentedA14 · Search order
The defaults command reads a domain from Terminal: defaults read <bundle identifier>.documentedA14 · Defaults tool
A command-line tool can read an app's domain through CFPreferences. dreader's CLI and app both read the DataRoot key of com.clubstraylight.dreader this way, because an app launched from the Finder does not see shell environment variables.familyD · ADR-0010 layer 1
On macOS 26, defaults delete <domain> leaves an empty <domain>.plist in ~/Library/Preferences, still listed by defaults domains; deleting the file first is undone, because the preferences daemon writes it back with its cached values. Found by dreader's uninstaller tests.observedO2 · DR-0046, 2026-10-13
com.clubstraylight.dreader.plist exists in this account's ~/Library/Preferences.observedO1 · 2026-10-13

§5

The sandbox container

factkindsource
App Sandbox "restrict[s] access to system resources and user data in macOS apps to contain damage if an app becomes compromised", by "limiting your app's access to resources requested through entitlements". "To distribute a macOS app through the Mac App Store, you must enable the App Sandbox capability." The entitlement is com.apple.security.app-sandbox.documentedA9 · Overview
"macOS apps that are sandboxed have all their Application Support, Cache, temporary directories and other related documents stored within a directory located at a system-defined path", obtained with NSHomeDirectory(). The Containers directory holds "the home directories for any sandboxed apps".documentedA1 · Library; A2 · Containers
A sandboxed app reaches files outside its container through the user's choice in an Open or Save panel (com.apple.security.files.user-selected.read-only or read-write) or through folder entitlements (Downloads, Pictures, Music, Movies). com.apple.security.files.all is deprecated.documentedA9 · Entitlements
The container's exact path (~/Library/Containers/<bundle id>/Data by common account) was not confirmed from the pages read at this version.unverified—
dreader is not sandboxed, by decision: a Developer ID build "can be unsandboxed and read books wherever the user keeps them"; an App Store build would move its root into the container and need security-scoped bookmarks for books outside it.familyD · ADR-0010, "Delivering dreader as a product"; PRD-0002 non-goals

§6

What a Tauri app resolves

Tauri's PathResolver maps the conventional directories to macOS paths. ${bundle_identifier} is identifier in tauri.conf.json, which must be reverse-DNS, unique, and alphanumeric with hyphens and periods, because it "is used in system configuration such as the bundle ID and the webview data directory path".

Places in no Apple list

§8

Relationships

  • Arrival puts a bundle in /Applications or ~/Applications (§2) and registers it in a database outside any of these directories (arrival §6).
  • The gate decides whether the app may read ~/Documents, ~/Desktop, ~/Downloads at all (gate §6); Apple's rule in §2 is about writing, the privacy system's about reading.
  • Removal is the inverse of §3 and §7: every directory here that carries the app's name or identifier is residue after the bundle is gone (removal §2).
  • dreader keeps its record under Application Support by Apple's rule for "files that contain user data", and resolves the path itself rather than through Tauri (§6), so that its CLI agrees with the app (dreader §1).

§9

Gaps and unverified claims

  • The File System Programming Guide is an archive document. Its rules held on this Mac wherever they were checked, but Apple has not revised it for macOS 26; a current-generation statement of the same rules was not found.
  • The sandbox container's internal layout and the location of the privacy permissions database were not read.
  • ~/Library/Group Containers and the Keychains directory are not on this page.
  • The preferences daemon (cfprefsd) is named in dreader's test, not in the Apple page read; its caching behaviour is observed only.
