CI/CD: pipeline artifacts and the documents that require them

A build and delivery pipeline produces records of what it built, such as component lists, attestations, scan results, and signatures. Federal guidance, Defense Department policy, and security controls refer to these records. Each page of this atlas covers one artifact or practice, read from the issuing bodies' documents: its definition, its history, the documents that refer to it, and the controls it is evidence for. The first page is the software bill of materials (glossary: SBOM).

subject
Continuous integration and delivery as a source of security evidence. The pages are about the artifacts and the documents that govern them, not about any one CI product.

Each page lists the documents it was read against and the date. The SBOM page: EO 14028; NTIA 2021-07-12; SSDF 1.1 and the 1.2 draft; SP 800-53 Rev. 5; SP 800-204D; ASD STIG V6R4; the DoD cATO memorandum, guide, and evaluation criteria; OMB M-26-05; read 2026-11-14.

§1

Where evidence arises in a pipeline

The stages are the ones NIST SP 800-204D gives a pipeline: "source code through the build, test, package, and deployment stages" (§1.1). The evidence at each stage links to its page where one exists.

1sourceDependencies are declared and locked. A Source SBOM is read from them.
2buildThe artifact is made. A Build SBOM records what went into it; a build attestation records how it was made. Attestation has no page yet.
3testScanners read the component list against advisories; static and dynamic analysis read the code. No page yet.
4packageThe release is hashed and signed, the SBOM with it. An Analyzed SBOM can be made from the package by a third party.
5deployWhat is installed is recorded: a Deployed or Runtime SBOM, and the system's component inventory.

§3

How to read a page

  • The block under the title lists the documents the page was read against and when. The change record at the end keeps the old fact when a new document replaces it.
  • A row's source mark links to the document in the page's sources list and gives the place in it. Verbatim wording is quote-marked.
  • A control mapping says whose it is: the issuing body's own cross-reference, or the page's reading of the control text. An artifact is evidence toward a control; the control also asks for a process.
  • A row marked unverified says why: a secondary source, or a primary one that refused the fetch. Each page's gaps section lists what the author knows to be missing.
