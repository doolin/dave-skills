CI/CD: pipeline artifacts and the documents that require them

A build and delivery pipeline produces records of what it built, such as component lists, attestations, scan results, and signatures. Federal guidance, Defense Department policy, and security controls refer to these records. Each page of this atlas covers one artifact or practice, read from the issuing bodies' documents: its definition, its history, the documents that refer to it, and the controls it is evidence for. Twelve pages so far, one per artifact the portfolio's three pipelines produce (§2), starting with the software bill of materials (glossary: SBOM).

§1

Where evidence arises in a pipeline

The stages are the ones NIST SP 800-204D gives a pipeline: "source code through the build, test, package, and deployment stages" (§1.1). The evidence at each stage links to its page where one exists.

1sourceThe repository and its history are scanned for credentials (secrets scan) and the code is linted and analyzed (static analysis). Dependencies are declared and locked; a Source SBOM is read from them.
2buildThe artifact is made. A Build SBOM records what went into it; build provenance records how it was made.
3testThe tests run (test results), with the code they executed measured (coverage); scanners read the dependencies against advisories (vulnerability scan).
4packageThe release is hashed and signed, its digest with the provenance. An Analyzed SBOM can be made from the package by a third party.
5deployWhat is installed is recorded: a Deployed or Runtime SBOM, and the system's component inventory.

Across the stages, a run keeps a record of itself: each job's audit events, a hashed evidence manifest of everything it produced, OSCAL documents stating which controls the evidence supports, a trusted timestamp, and the attestation that archives the bundle and anchors its hash.

§4

How to read a page

  • The block under the title lists the documents the page was read against and when. The change record at the end keeps the old fact when a new document replaces it.
  • A row's source mark links to the document in the page's sources list and gives the place in it. Verbatim wording is quote-marked.
  • A control mapping says whose it is: the issuing body's own cross-reference, or the page's reading of the control text. An artifact is evidence toward a control; the control also asks for a process.
  • A row marked unverified says why: a secondary source, or a primary one that refused the fetch. Each page's gaps section lists what the author knows to be missing.
