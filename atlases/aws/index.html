What the AWS tools the family runs actually do

The family deploys to and backs up into AWS through the AWS CLI. Its high-level commands make decisions the operator never sees: which files to send, which to skip, which to delete. This atlas reads those decisions from the vendor's own documents, the help text the installed CLI ships and the CLI's source at the matching tag, one page per command or feature. It opens with aws s3 sync.

§1

The mechanism of a sync, in five stages

The stages the CLI runs, in its own order (CommandArchitecture.create_instructions). Each links to its section on the s3 sync page.

1listBoth sides are listed in the same order: the local tree depth-first with each directory's entries sorted, S3 through ListObjectsV2; the next stage assumes the two lists share one order.
2filter--exclude and --include run over both listings, the last matching pattern deciding.
3pairOne walk down both sorted lists pairs each source file with the destination file of the same relative name, or with nothing.
4decideA sync strategy says yes or no for each pair: by size and modification time, by default; the rule differs by direction.
5transferThe yes items go to the transfer client: uploads, downloads, copies, and with --delete deletions, concurrently, multipart above a threshold.

§2

The rule in one table

When a file is on both sides, with no flag. The detail, the flags, and the citations are on the s3 sync page.

directiontransfers whenskips a same-sized file when
upload (local → S3)the sizes differ, or the local file is newer than the objectthe object is as new as the local file or newer
copy (S3 → S3)the sizes differ, or the source object is newer than the destination objectthe destination is as new as the source or newer
download (S3 → local)the sizes differ, or the local file is newer than the objectthe local file is as old as the object or older, including when the object changed after the last download
The one sentence to keep. A sync compares sizes and times, never contents, and on a download it sends an object again only when the local copy is newer than it, not older; an object rewritten in S3 at the same size is not downloaded unless --exact-timestamps is given (s3 sync §7).

§3

How to read a page

  • The block under the title names the CLI version the page was read against and when. A fact is true at that version; the change record at the end keeps the old fact when a release changes it.
  • A row's source mark (C2 · compare_time) names a document in the page's sources list and the place in it the fact came from. Verbatim vendor wording, the source's included, is quote-marked or set as code.
  • Where the vendor's help text and its source disagree, the page says so and states which one the command follows: the source is what runs.
  • Each page's gaps section lists what the author knows to be missing, so "not on the page" can be told from "not known".
